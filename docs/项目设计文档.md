# ROS2 多机器人任务调度与监控系统 · 设计文档

> 版本：v0.1（待评审）
> 日期：2026-10-21
> 目标岗位：机器人上位机开发 / 机器人系统集成（ROS2 应用）

---

## 1. 项目定位

**一句话**：两台 TurtleBot3 在 Gazebo 中自主巡逻，用相机识别不同颜色的任务物块，把"发现目标"上报给调度中心，调度中心生成任务并分配给最近的空闲机器人，机器人导航到目标附近后做视觉对位并完成任务，全过程可在 RViz 中监控。

**它证明的能力**（面试可讲的点）：

| 能力 | 在本项目中的落点 |
|---|---|
| ROS2 通信建模 | 话题（状态/检测）、服务（提交/取消任务）、动作（导航，带反馈） |
| 多机隔离 | namespace、TF 前缀、独立桥接条目、独立参数 |
| 传感器接入 | Gazebo 相机 → ros_gz_bridge → cv_bridge → OpenCV |
| 视觉处理 | HSV 颜色分割、形态学、轮廓筛选、单目测距 |
| 控制闭环 | odom 反馈的 P 控制 + 视觉伺服对位 |
| 工程可靠性 | 任务超时、失败重试、状态机、并发互斥 |
| 可观测性 | RViz 集群视图、rosbag 回放、结构化日志 |

**明确不做**：SLAM 建图、全局路径规划与动态避障、深度学习检测、真机联调。仿真验证为主，避免陷入算法深水区。

## 2. 系统架构

```
┌───────────────────────────── Gazebo (fleet 世界) ─────────────────────────────┐
│  robot1: 底盘 + RGB 相机          robot2: 底盘 + RGB 相机        彩色物块 ×3    │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │ gz 话题
                    ┌───────────▼───────────┐
                    │  ros_gz_bridge        │  每车：image / camera_info / odom
                    │  (bridge.yaml)        │  scan / imu / joint_states / cmd_vel / tf
                    └───────────┬───────────┘
                                │ ROS2
        ┌───────────────────────┼──────────────────────────┐
        │                       │                          │
┌───────▼────────┐     ┌────────▼─────────┐      ┌─────────▼────────┐
│ fleet_perception│     │   robot_agent    │      │  fleet_manager   │
│ 颜色检测+测距   │     │  导航/对位/状态机 │      │ 任务队列/分配/超时│
│ 发布 Detection  │     │  动作服务端      │      │ 状态聚合         │
└───────┬────────┘     └────────┬─────────┘      └─────────┬────────┘
        │  /robotN/detection    │ /robotN/status           │ /fleet/tasks
        └───────────────────────┴──────────┬───────────────┘
                                           │
                                 ┌─────────▼─────────┐
                                 │  RViz2 监控视图    │
                                 │  模型/相机/任务标记 │
                                 └───────────────────┘
```

### 分层职责

| 层 | 包 | 职责 | 不该做的事 |
|---|---|---|---|
| 仿真层 | fleet_bringup | world、模型、桥接、launch、rviz 配置 | 不含业务逻辑 |
| 接口层 | fleet_msgs | 所有自定义 msg/srv/action | 不依赖其他业务包 |
| 感知层 | fleet_perception | 图像 → 目标颜色/位置 | 不发控制指令 |
| 执行层 | robot_agent | 接任务、导航、对位、上报 | 不做全局分配 |
| 调度层 | fleet_manager | 生成任务、分配、超时重试、聚合状态 | 不直接控制底盘 |

## 3. 仿真环境改造

### 3.1 给每台车加相机

- 在 `model.sdf` 的 `base_scan` 同级增加 `camera_link`，挂 `<sensor type="camera">`：
  - 分辨率 640×480，频率 15 Hz，`horizontal_fov` 1.047（60°）
  - 话题 `/robotN/camera/image`，`<gz_frame_id>robotN_camera_link</gz_frame_id>`
  - 位置：车头前方 0.05m、高 0.15m，俯角约 15°（保证物块在画面下方 1/3）
- URDF 同步增加 `camera_link` 与 `camera_joint`（launch 里的统一加前缀逻辑会自动处理）
- `bridge.yaml` 增加：
  - `/robotN/camera/image`：`sensor_msgs/msg/Image` ↔ `gz.msgs.Image`
  - `/robotN/camera/camera_info`：`sensor_msgs/msg/CameraInfo` ↔ `gz.msgs.CameraInfo`

> 选 RGB 而非 RGBD：软件渲染下深度相机开销明显更大，而单目测距（已知物块尺寸）就能满足对位精度，且更容易讲清楚原理。

### 3.2 任务物块

- 世界中放置 3 个 0.2m 立方体，颜色分别红/绿/蓝，位置互不遮挡（如 (2.5, 1.5)、(4, -1.2)、(1.5, 3)）
- 物块只在视觉里被"发现"，调度中心初始不知道位置 —— 这样"发现目标 → 生成任务"才成立
- 世界文件：`worlds/fleet_tasks.sdf`（在 `fleet_empty.sdf` 基础上加物块与地面纹理）

### 3.3 启动与可视化重建

- `fleet_sim.launch.py`：整体保留现有结构，新增相机桥接；RViz 用 `TimerAction` 延迟 6s 启动（已验证可避免相机初始化错位）
- `fleet.rviz`：
  - 两个 RobotModel（`/robotN/robot_description`）
  - 两个 Image 显示（`/robotN/camera/image`）
  - 两个 LaserScan、两个 Odometry、TF、Grid
  - 一个 MarkerArray（`/fleet/task_markers`）显示任务状态
- launch 参数：`gui`（默认 false）、`rviz`（默认 true）、`perception`（默认 true，可关掉感知单独调调度）

## 4. 接口设计（fleet_msgs）

### 4.1 消息

**Task.msg**

```
# 常量
uint8 TYPE_APPROACH=1      # 靠近并确认目标
uint8 TYPE_SEARCH=2        # 巡逻搜索（可预留）

string task_id
uint8 type
uint8 target_color         # 1=RED 2=GREEN 3=BLUE
geometry_msgs/Pose target_pose
builtin_interfaces/Time created_at
```

**TaskStatus.msg**

```
uint8 STATE_PENDING=0
uint8 STATE_ASSIGNED=1
uint8 STATE_NAVIGATING=2
uint8 STATE_DOCKING=3
uint8 STATE_DONE=4
uint8 STATE_FAILED=5

string task_id
string robot_id
uint8 state
float32 progress          # 0.0 ~ 1.0
string detail             # 失败原因/当前动作
builtin_interfaces/Time stamp
```

**RobotStatus.msg**

```
uint8 STATE_IDLE=0
uint8 STATE_BUSY=1
uint8 STATE_ERROR=2

string robot_id
uint8 state
geometry_msgs/Pose2D pose
string current_task
uint16 tasks_done
uint16 tasks_failed
builtin_interfaces/Time stamp
```

**Detection.msg**

```
uint8 COLOR_RED=1
uint8 COLOR_GREEN=2
uint8 COLOR_BLUE=3

builtin_interfaces/Time stamp
uint8 color
float32 confidence         # 轮廓面积/参考面积，用于去抖
sensor_msgs/RegionOfInterest bbox
geometry_msgs/Point world_pose   # 单目测距 + odom 推算
```

### 4.2 服务

**SubmitTask.srv**（供外部/测试注入任务，也是调度器内部生成任务后的发布入口）

```
uint8 target_color
geometry_msgs/Pose target_pose
---
bool accepted
string task_id
string message
```

**CancelTask.srv**

```
string task_id
---
bool canceled
string message
```

### 4.3 动作

**NavigateTo.action**（robot_agent 提供，fleet_manager 调用）

```
# Goal
geometry_msgs/Pose target_pose
float32 standoff        # 距目标停下的距离，默认 0.6m
---
# Result
bool reached
float32 final_distance
string message
---
# Feedback
float32 distance_remaining
float32 heading_error
```

> 导航先用"原地转向对准 → 直线前进 + 航向修正"的两级 P 控制（与已完成的 go_to_goal 逻辑一致），不做避障。

### 4.4 话题一览

| 话题 | 类型 | 方向 |
|---|---|---|
| `/robotN/detection` | Detection | 感知 → 调度 |
| `/robotN/status` | RobotStatus | agent → 调度/监控 |
| `/fleet/tasks` | Task | 调度 → 各 agent |
| `/fleet/task_status` | TaskStatus | agent → 调度/监控 |
| `/fleet/task_markers` | MarkerArray | 调度 → RViz |
| `/robotN/camera/image` | Image | 仿真 → 感知/RViz |

## 5. 感知设计（OpenCV）

### 5.1 处理流水线

```
Image(640×480) 
   → cv_bridge 转 cv::Mat
   → 缩放到 320×240（降负载，保持比例）
   → BGR → HSV
   → 三色并行 inRange（红需两段 H 合并）
   → 形态学：开运算去噪 + 闭运算补洞（5×5）
   → findContours，过滤面积 < 200 px²
   → 取最大轮廓作为该颜色的候选
   → 质心 (u,v)、外接框宽度 w
   → 单目测距与方位角
   → 发布 Detection（每色一条，最多 3 条/帧）
```

### 5.2 颜色阈值（初值，需现场标定）

| 颜色 | H | S | V |
|---|---|---|---|
| 红 | 0–10 与 170–180 | 120–255 | 70–255 |
| 绿 | 40–80 | 100–255 | 60–255 |
| 蓝 | 100–130 | 120–255 | 60–255 |

参数通过 ROS2 参数暴露（`red_h_min` 等），支持 `ros2 param set` 在线调；调好后写入 `config/perception.yaml`。

### 5.3 单目测距

已知物块宽度 `W=0.2m`，相机焦距由 `camera_info` 或 HFOV 计算：

```
f = (image_width / 2) / tan(hfov / 2)        # 640×480, 60° → f ≈ 554 px
distance = f * W / w_pixels                   # 距离
bearing  = atan((u - cx) / f)                 # 相对相机光轴的水平偏角
```

再结合 `/robotN/odom` 的位姿与相机安装外参，把目标换算到 `world`：

```
目标世界坐标 = 机器人位姿 ⊕ 相机外参 ⊕ (distance, bearing)
```

- 有效距离区间：0.5–5.0 m（对应像素宽 22–220 px）
- 超出区间或面积过小 → 丢弃该检测
- 误差预期：±0.2 m（仿真无噪声，主要误差来自物块朝向与俯角标定）

### 5.4 去抖

同一颜色连续 3 帧满足 `|Δu| < 10px 且 |Δd| < 0.15m` 才发布，避免调度器收到一堆抖动任务。

## 6. 调度设计（fleet_manager）

### 6.1 任务生成

```
收到 Detection
  → 与已有任务比对：同色 且 相距 < 0.5m 视为同一目标 → 忽略
  → 否则生成 PENDING 任务（task_id = color + 时间戳）
  → 发布 /fleet/tasks（供 agent 观察）+ 内部入队
```

### 6.2 分配策略

- 触发条件：有新 PENDING 任务，或某机器人变 IDLE，或任务超时重排
- 策略：**最近空闲优先** —— 在 IDLE 机器人中选到目标欧氏距离最小者
- 平局按 `robot_id` 字典序，保证结果可复现
- 分配后：任务 → ASSIGNED，机器人 → BUSY，调用 `NavigateTo` 动作

### 6.3 状态机

```
任务：PENDING → ASSIGNED → NAVIGATING → DOCKING → DONE
                    │           │           │
                    └───────────┴───────────┴──→ FAILED（超时/目标丢失/动作失败）

机器人：IDLE → BUSY → IDLE
                 └──→ ERROR（连续失败 ≥ 2，需人工重置）
```

- 单任务超时 90s；超时后重新入队一次，二次超时 → FAILED
- 机器人执行失败上报 `detail`（如"目标丢失""导航超时"）
- 调度器单线程 + 互斥锁保护任务表与机器人表；回调只投递事件，状态变更集中在 `spinOnce` 处理，避免并发竞态

### 6.4 并发约束

- 一台车同时只执行一个任务
- 两个任务目标距离 < 1.0m 时，后分配的任务等待（避免两车抢同一物块）

## 7. 视觉对位（robot_agent DOCKING 阶段）

到达目测位置（距目标约 1.2m）后切视觉伺服：

```
每帧 Detection：
  e_u = (u - cx) / (W/2)                    # 归一化横向误差
  angular.z = -Kp_yaw * e_u                 # Kp_yaw = 1.5
  e_d = d_current - 0.6                     # 期望停在 0.6m
  linear.x  = clamp(Kp_dist * e_d, -0.1, 0.15)
  若 |e_u| < 0.03 且 |e_d| < 0.1 → 停车，任务 DONE
  若连续 15 帧无检测 → 后退 0.3m 重新搜索，3 次后 FAILED
```

- 控制周期由相机帧（15 Hz）驱动，odom 只做距离兜底
- 停车后发布 TaskStatus(DONE)，调度器释放机器人

## 9. 包结构与职责

```
fleet_ws/src/
├── fleet_msgs/            # msg / srv / action
├── fleet_bringup/         # world / models / bridge / launch / rviz（重建）
├── fleet_perception/      # C++ / OpenCV 颜色检测 + 测距
├── robot_agent/           # C++ 导航动作服务端 + 状态机 + 视觉对位
└── fleet_manager/         # C++ 任务队列 + 分配 + 超时 + Marker 发布
```

- 全部节点用 **C++**（不使用 Python 节点）
- 回调统一用 lambda 转发（既定约定，不用 `std::bind`）
- 每包自带 `config/*.yaml`，参数不写死在代码里

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 软件渲染下相机掉帧 | 检测不稳 | 图像降到 320×240 处理；相机 15Hz；必要时关 RViz 相机显示 |
| 光照/阴影导致阈值漂移 | 漏检误检 | HSV 阈值参数化；物块用高饱和材质；只保留最大轮廓 |
| 单目测距受俯角误差影响 | 目标坐标偏差 | 相机外参写进 URDF；用已知距离标定一次，记录误差 |
| 两车同时发现同一物块 | 重复任务 | 调度器按"同色 + 0.5m"去重 |
| 动作/状态机竞态 | 状态错乱 | 回调只投递事件，单线程处理；任务表加锁 |
| 软件渲染 CPU 占用高 | 仿真卡顿 | `gui:=false`；RViz 延迟启动；必要时降到 1 车调试 |

## 12. 待确认项

1. 物块是否需要可被推动（体现"搬运"）？当前设计为静态目标，只做接近与确认。
2. 相机俯角 15° 是否合适，需要在 M1 用实际画面校准。
3. 巡逻搜索是否纳入 M5？当前设计里机器人 IDLE 时静止；若要"主动搜索"，需加 4 个巡逻点循环。
4. 监控是否要求 Web 面板？当前验收只到 RViz。

## 13. 实施顺序

```
M1 仿真底座（相机/物块/launch/rviz 重建）
 → M2 fleet_msgs
 → M3 fleet_perception（可脱离调度单独验证）
 → M4 robot_agent（可手动发目标位姿验证）
 → M5 fleet_manager（接上感知与执行）
 → M6 演示与回放
```

每个里程碑完成后做一次验收记录，验收不通过不进入下一阶段。
